# Single Page Application (SPA) Support

## Problem with SPAs

Single Page Applications (SPAs) are websites that load content dynamically using JavaScript. Examples include:
- React applications
- Vue.js applications
- Angular applications
- Next.js (client-side routing)
- Other modern JavaScript frameworks

### Why Traditional Scraping Fails

Traditional HTML parsing (using `requests` + `BeautifulSoup`) fails because:

1. **Initial HTML is minimal**: The server returns a basic HTML shell with minimal content
2. **Content loads via JavaScript**: Real content and links are generated by JavaScript after page load
3. **Client-side routing**: Links may not have traditional `href` attributes (e.g., React Router uses `onClick` handlers)
4. **Dynamic rendering**: Content appears only after JavaScript executes

**Example SPA HTML (initial response):**
```html
<!DOCTYPE html>
<html>
<head><title>My App</title></head>
<body>
  <div id="root"></div>
  <script src="/app.js"></script>
</body>
</html>
```

The actual links and content are only visible after JavaScript executes!

## Solution: Browser Mode

The scraper now supports **browser mode** using Playwright, which:

1. **Renders JavaScript**: Executes JavaScript like a real browser
2. **Waits for content**: Waits for page to fully load before extracting links
3. **Extracts dynamic links**: Finds links generated by JavaScript frameworks
4. **Handles client-side routing**: Detects router links from React, Vue, Angular

## Installation

Browser mode requires Playwright:

```bash
# Install Playwright Python package
pip install playwright

# Install browser binaries (one-time setup)
playwright install chromium
```

Or install all browsers:
```bash
playwright install
```

## Usage

### Basic SPA Crawling

```bash
# Enable browser mode for JavaScript rendering
python main.py \
  --seed-urls https://example-spa.com \
  --max-urls 100 \
  --use-browser
```

### Browser Wait Options

Control when the browser considers the page "ready":

```bash
# Wait for network to be idle (default - best for most SPAs)
python main.py --seed-urls https://example.com --max-urls 100 --use-browser --browser-wait-for networkidle

# Wait for DOM content loaded (faster, but may miss async content)
python main.py --seed-urls https://example.com --max-urls 100 --use-browser --browser-wait-for domcontentloaded

# Wait for page load event (slower, waits for all resources)
python main.py --seed-urls https://example.com --max-urls 100 --use-browser --browser-wait-for load

# Wait for navigation commit (fastest, but may miss content)
python main.py --seed-urls https://example.com --max-urls 100 --use-browser --browser-wait-for commit
```

**Recommendation**: Use `networkidle` (default) for most SPAs - it waits until network activity settles, ensuring JavaScript has finished loading content.

### Complete Example

```bash
python main.py \
  --seed-urls https://my-react-app.com \
  --max-urls 200 \
  --max-depth 3 \
  --use-browser \
  --browser-wait-for networkidle \
  --timeout 30 \
  --output-format JSON
```

## How It Works

### 1. Browser Rendering

When `--use-browser` is enabled:
- Launches a headless Chromium browser
- Navigates to each URL
- Waits for JavaScript to execute
- Extracts the fully rendered HTML

### 2. Link Extraction

The browser mode extracts links from:

**Traditional links:**
- `<a href="...">` tags
- `<link href="...">` tags

**SPA-specific links:**
- React Router: `data-path` attributes, `onClick` handlers
- Vue Router: `router-link` components with `to` attributes
- Angular Router: `routerlink` attributes
- JavaScript-generated links in `onclick` handlers

### 3. Performance Considerations

**Browser mode is slower** than traditional scraping:
- Each page requires browser startup/rendering
- JavaScript execution takes time
- More memory and CPU usage

**Recommendations:**
- Use browser mode only when needed (SPAs)
- Lower `--max-concurrent` for browser mode (default: auto-limited to 3)
- Increase `--timeout` for slow-loading SPAs (default: 10s, try 30s)
- Use `networkidle` wait strategy for best results

## When to Use Browser Mode

### ✅ Use Browser Mode For:
- React/Vue/Angular applications
- Sites with client-side routing
- Pages that load content via JavaScript
- Dynamic content that appears after page load
- Sites where traditional scraping finds no/few links

### ❌ Don't Use Browser Mode For:
- Traditional server-rendered websites
- Static HTML sites
- Sites that work fine with traditional scraping
- When speed is critical (browser mode is slower)

## Comparison

### Traditional Mode (Default)
```bash
python main.py --seed-urls https://example.com --max-urls 100
```
- ✅ Fast
- ✅ Low resource usage
- ❌ Can't see JavaScript-rendered content
- ❌ Misses SPA links

### Browser Mode
```bash
python main.py --seed-urls https://example.com --max-urls 100 --use-browser
```
- ✅ Sees JavaScript-rendered content
- ✅ Finds SPA links
- ✅ Handles client-side routing
- ❌ Slower
- ❌ Higher resource usage

## Troubleshooting

### Playwright Not Installed
```
Error: Playwright is not installed
```
**Solution:**
```bash
pip install playwright
playwright install chromium
```

### Timeout Errors
```
Timeout loading https://example.com
```
**Solution:** Increase timeout
```bash
python main.py --seed-urls https://example.com --use-browser --timeout 60
```

### Missing Links
If browser mode still misses links:
1. Try `--browser-wait-for networkidle` (default)
2. Increase `--timeout`
3. Check if links are behind authentication (not supported)
4. Verify the site actually loads content via JavaScript

### High Memory Usage
Browser mode uses more memory. If you encounter issues:
- Reduce `--max-concurrent` (browser mode auto-limits to 3)
- Process fewer URLs at once
- Close other applications

## Advanced: Hybrid Approach

You can't mix browser and non-browser mode in a single crawl, but you can:

1. **Crawl static pages first** (fast):
```bash
python main.py --seed-urls https://example.com/static --max-urls 50
```

2. **Then crawl SPA pages** (slower but complete):
```bash
python main.py --seed-urls https://example.com/app --max-urls 50 --use-browser
```

## Framework-Specific Notes

### React (React Router)
- Extracts links from `onClick` handlers
- Finds `data-path` attributes
- Detects `Link` components

### Vue.js (Vue Router)
- Extracts `router-link` components
- Finds `to` attributes
- Handles dynamic routes

### Angular
- Extracts `routerlink` attributes
- Finds router navigation links

### Next.js
- Works with both server and client-side routes
- Detects `Link` components

## Best Practices

1. **Start without browser mode**: Try traditional scraping first - it's faster
2. **Use browser mode when needed**: Only enable for SPAs or JavaScript-heavy sites
3. **Adjust timeout**: SPAs may need 30-60 seconds to fully load
4. **Monitor resources**: Browser mode uses more CPU/memory
5. **Test with small max-urls first**: Verify it works before large crawls
